# IDLE ORBIT 設計書

## 1. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 / FW | Dart / Flutter (stable) | Android・iOS 単一コードベース |
| ゲーム描画 | Flame | メイン画面の惑星シーンのみ。UIは Flutter で作り、Flame は「見せる」部分に限定して軽量化 |
| UI | Material 3（ダークネイビー独自テーマ） | 長時間プレイでも疲れにくい低彩度サーフェス＋資源色のアクセント |
| 状態管理 | `provider` + `ChangeNotifier`（`GameController`） | 依存が少なく十分。ロジックは純粋Dartに分離済み |
| 保存 | `shared_preferences` に JSON 1ドキュメント＋バックアップ | 数KBを丸ごと読み書きするため SQLite より単純で堅牢。`KeyValueStore` 抽象で後から差し替え可能 |
| 広告 | `google_mobile_ads`（UMP 同意フロー込み） | 抽象 `AdService` 経由 |
| 課金 | `in_app_purchase`（Play Billing / StoreKit） | 抽象 `PurchaseService` 経由 |
| 分析 | 抽象 `AnalyticsService`（初期はローカルログ） | Firebase は後から実装を追加するだけ |

### レイヤー分離

```
features/ (画面) ──▶ GameController ──▶ engine/ (純粋ロジック) ──▶ model/, config/
                         │
                         ├─▶ data/ (SaveRepository)
                         └─▶ services/ (Ad / Purchase / Analytics の抽象)
```

- `engine/` は Flutter・時計・通信に依存しない。時刻は常に `nowMs` 引数で受け取るため決定的にテスト可能。
- 広告・課金・分析はインターフェース越しに注入。未設定・失敗時は `DisabledAdService` / `UnavailablePurchaseService` になり、ゲーム本体はそのまま遊べる。

## 2. ゲームシステム

### 2-1. 生産モデル

- 生産施設（採掘・発電）: `基本値 × レベル × マイルストーン倍率 × 生産倍率 × ブースト`
- 変換施設（精錬・研究）: 入力資源を消費。入力が不足すると**比例配分で稼働率が低下**（UIに稼働率表示）
- 保管施設: 鉱石・エネルギー・合金の上限を `基本上限 × 1.6^Lv × 研究補正` に。研究ポイントは上限なし
- 上限に達すると生産は停止するが、報酬・購入で得た分は上限を超えても**削らない**
- 生産倍率は「ロボット」「研究」「転生」を別々の乗算バケットにし、各システムの価値が埋もれないようにした。さらに惑星・実績・司令官レベル・プレミアムが乗算

### 2-2. 放置報酬

- 経過時間は **最大の観測時刻（highWaterMs）** から計算
- 時刻が highWater より2分以上過去 → 報酬なし＋理由を表示。巻き戻し→早送りでの二重取りは不可
- 上限8時間（`balance.json` の `offline.baseCapHours`、研究「自律運転」・プレミアムで延長）
- 放置効率 60%（輸送ボット・転生強化で上昇）。広告視聴で2倍（任意）
- 計算はオフラインシミュレーション（60秒刻み）。ブーストの期限切れ・変換施設の資源不足・保管上限を正しく反映
- 未受取の報酬はセーブに保存（受取前にアプリを落としても消えない・二重に増えない）
- プレイ中の時間経過はモノトニック時計（Stopwatch）で計測し、プレイ中の時刻変更は影響しない

### 2-3. 進行と目標設計

- 「次の目標」カードを常時表示（次の惑星と必要資源の進捗バー）
- バランスシミュレーター（貪欲プレイ・アクティブのみ）の結果：

| 到達 | アクティブ時間 | 想定実時間（放置込み） |
|---|---|---|
| 惑星2 グラシエ | 約16分 | 初回セッション内 |
| 惑星3 デューンベル（転生解放） | 約1時間40分 | 1日目 |
| 惑星4 ヴァルカラ | 約15時間 | 2〜4日目 |
| 惑星5 未知の惑星 | 転生なしでは48時間以上 | 1〜2週目（転生前提） |

`test/game/balance_test.dart` が序盤ペースの回帰を防止。

### 2-4. 転生（星系ワープ）

- 解放条件: 惑星3の開拓。ポイント = floor(√(今回の合金生産量 / 2000))
- リセット: 資源・施設・ロボット・研究・惑星
- 維持: ワープポイント/強化・実績・ミッション・司令官レベル・購入品（特典ロボット含む）
- 強化: 全生産 / 放置効率 / ロボット性能 / 初期資源支給。画面で「リセットされるもの / 引き継がれるもの」を明示

### 2-5. デイリー・実績

- ログインボーナス: 7日周期（途切れてもリセットしない＝罰のない設計）
- デイリーミッション: プールから日付シードで3件。指標は「その日の開始時点からの差分」。日付は前進のみ（時刻巻き戻しで再受取不可）
- 実績: 受け取ると恒久的な全生産ボーナス（+2〜10%）。受取操作がミッション画面への再訪動機になる
- ミッション・実績は `balance.json` に追加するだけで増やせる

## 3. 収益化設計

### 3-1. リワード広告（任意視聴のみ）

| 場所 | 報酬 |
|---|---|
| 放置報酬 | 2倍で受け取り |
| 生産ブースト | 30分 ×2（最大4時間まで延長可） |
| 補給物資 | 現在の生産20分ぶん（30分クールダウン） |
| ログイン7日目等 | ブースト付与（広告不要の報酬） |

- 報酬は `onUserEarnedReward` を受けた場合のみ付与。ロード失敗・途中終了は付与せずメッセージ表示
- 失敗時、放置報酬は保持されたまま（再試行可能）
- 広告非対応ビルドではボタンを「広告は利用できません」と無効表示（押しても失敗するボタンを残さない）

### 3-2. インタースティシャル

- 表示タイミング: サブ画面（惑星・転生）を閉じた時、惑星開拓演出の後 **のみ**
- 制限: セッション開始3分以内は出さない／間隔 標準5分・少なめ10分（設定で変更）／1セッション最大4回／リワード視聴後2分は出さない／広告削除購入者には出さない
- 全て `balance.json` の `ads.interstitial` で調整可能

### 3-3. アプリ内課金

| 商品 | 種別 | 内容 | 仮価格 |
|---|---|---|---|
| 広告削除 | 非消耗 | インタースティシャル非表示 | ¥480 |
| 初心者パック | 非消耗 | 合金500・研究100・開拓者ボット（転生後も保持） | ¥160 |
| 生産ブースト24h | 消耗 | 24時間 生産×2（広告ブーストと乗算） | ¥250 |
| プレミアムパック | 非消耗 | 全生産+50%・放置上限+4h・広告削除・リワード広告スキップ・特別外観 | ¥1,200 |

- 付与はストアの `purchased / restored` イベントでのみ。**付与→保存→completePurchase** の順（クラッシュしても失われない）
- トランザクションIDで冪等化、非消耗品の復元で二重付与しない
- ストア未接続時は価格を表示せずボタン無効（購入成功を偽らない）
- テスト/本番の分離: dev は Play ライセンステスター / App Store Sandbox、prod は本番。コード側で購入を模擬する仕組みは持たない
- **今後**: サーバーレシート検証（有料UA前に必須）

## 4. データ保存

- 保存内容: 資源・施設・ロボット・惑星・研究・転生・統計・デイリー・実績・ブースト・未受取放置報酬・最終プレイ時刻/最大観測時刻・購入状態・設定・司令官XP
- 形式: `{"saveVersion": N, "state": {...}}`。`SaveMigrator` に「バージョンN→N+1」の関数を登録して移行
- 新しいアプリで作られたセーブを古いアプリで読んだ場合は読み込まずエラー（上書き事故防止）
- 保存のたびに直前のセーブをバックアップ。破損時はバックアップから復元し、破損データは別キーに退避してユーザーに通知
- 自動保存15秒ごと＋バックグラウンド移行時＋重要操作時

## 5. 分析設計

`AnalyticsEvents` に定義済み。個人情報は送らない（端末内ID以外の識別子を使わない方針）。設定画面でオプトアウト可能。

| KPI | 算出方法 |
|---|---|
| DAU / D1・D7継続率 | `session_start_custom`（Firebase導入後は自動の first_open / user_engagement） |
| 平均プレイ時間・セッション数 | `session_end_custom.duration_s` |
| 施設強化回数 | `facility_upgrade` |
| 惑星解放率 | `planet_unlock.index` |
| 転生率 | `prestige` |
| 広告視聴率 | `ad_rewarded_request / earned / failed`, `ad_interstitial_shown` |
| 課金率・ARPDAU・LTV | `purchase_success`（売上はストア／Firebase の収益イベントと突合） |

## 6-2. ローカル通知

- サーバー不要の端末内通知のみ。離脱時に最大2件を予約し、復帰時に全キャンセル
  - 保管庫が満杯になる時刻（30分以上先かつ放置上限より前の場合のみ）
  - 放置報酬が上限に達する時刻
- オプトイン制: 初めて放置報酬を受け取った直後にゲーム内で説明 → 「受け取る」を選んだ時だけOSの許可ダイアログを表示。設定画面で変更可
- 予約は非厳密アラーム（exact alarm 権限不要）

## 7. MVP の範囲

上記 Phase 1〜4 の全機能。リリース前に必須の残作業は Phase 5（アイコン、プライバシーポリシー、実機検証、ストア登録、本番ID設定）。

MVP後の改善候補（データを見て優先順位付け）:
- 惑星ごとの固有施設・固有ロボット
- 期間限定イベント・シーズンパス
- クラウドセーブ（機種変更対応）
- 研究ツリーの分岐化
